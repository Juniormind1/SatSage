# AGENTS.md — Regtest-Lab

Zusätzlich zur Root-Verfassung ([`../AGENTS.md`](../AGENTS.md)). Bei Konflikt gewinnt Root-HART.

Die portable Docker-/Linux-Anleitung liegt unter `lab/regtest/README.md`. `.data/` und Lab-Env bleiben lokal und sind nie zu committen.

- **Mainnet nie.** Lab/CI: **Regtest → Signet → Testnet nur Ausnahme**. Lab-Env getrennt von Prod-`.env` (kein eingebauter Multi-Chain-Schalter). Remote-Bot-Regeln: [`../GROK_BOT.md`](../GROK_BOT.md).
- Docker/Regtest-Lab hochfahren ist der Prüfweg auf **macOS, Linux und Grok-Bots**. **Windows:** kein Docker durch den Assistenten hochfahren. Die Verify-Skripte starten Docker auf Windows nicht; fehlt bitcoind/Electrs, kommt ein deutscher Hinweis (`lab/regtest/scripts/infra_check.py`) statt eines hängenden Connect. Auf `dev-juniormind` darf fehlende Infra den Prüfer mit Exit 0 beenden, auf `main` ist sie Pflicht.
- Vor dem Merge nach `main` und vor jedem Release (Tag `v*`, Image, Linux-Binary, StartOS-Paket): Unittests grün und Regtest-Labor grün (Workflow `Regtest-Labor`, Core + Electrs, `verify_rpc_allowlist.py`, `verify_electrs_gap.py`, `verify_tx_classify.py`, `verify_sanctions_hops.py`, `verify_quellen_inventar.py`, plus Userflow und Chaos). Wochenlauf auf `dev-juniormind` nur, wenn der Prüfpfad seit dem letzten grünen Labor geändert wurde. `verify_quellen_inventar.py` löscht je Quelle den Cache, verbindet nur diese eine Quelle und vergleicht UTXO-Bestand plus Herkunft aller Inventar-UTXOs. Quellen 1–3: eigener Electrum-Server, Pruned Node, Bitcoin Core · RPC. Danach P2P: Bestand über Compact Filter (Sockets nur in `p2p_nur_utxo_entdeckung`, die Herkunftssperre bleibt), Grau und Gelb (rote Ringe erwartet), Electrs auf demselben Cache, noch einmal Grau und Gelb (Ringe weg). `verify_p2p_traces.py` bleibt aus.
- Scan-Abbruch/Cache: Protokoll [`../doc/testprotokoll-scan-abbruch-cache.md`](../doc/testprotokoll-scan-abbruch-cache.md), Runner `lab/regtest/scripts/verify_scan_abort_cache.py`. Optional, nicht Q6, bis das Produkt grün ist. Docker auf Windows nicht starten.
- **P2P-Herkunft nicht testen.** `verify_p2p_traces.py` nicht starten, im Scan-Abbruch `Q-START-P2P` und `Q-START-KILL` nicht mitlaufen lassen. Grund und Datum: [`../doc/issues/p2p-herkunft.md`](../doc/issues/p2p-herkunft.md), Suite: [`../doc/test-inventar.md`](../doc/test-inventar.md). Frühestens 2027-01-08. Der Bestands-Schritt in `verify_quellen_inventar.py` bleibt davon unberührt.
- Electrs gegen dasselbe Inventar: `lab/regtest/scripts/verify_electrs_inventar.py`. Nur Electrs-`get_tx`, kein Core-Fallback. Optional, nicht Q6.
- Labor-Abrufe bleiben auf der Lab-Env: `pinne_lab_env` in `lab/regtest/scripts/infra_check.py`, vor und nach `import main`. Gap, Klassifikation, Sanktions-Hops und Quellen-Inventar rufen das auf. Eine persönliche `.env` setzt das Netz sonst beim nächsten Abruf auf Mainnet zurück.
- Electrs-Gap über 100 ist Q6: `generate_scenarios.py` legt `lab-gap` an (Empfang #0 und #101, dazwischen leer). Nicht in `WALLET_*`. Prüfer `lab/regtest/scripts/verify_electrs_gap.py` (oder `--gap-only` auf einer bestehenden Chain). Limit 100 übersieht #101, Limit 101 findet den Outpoint. Docker auf Windows nicht starten.
- GUI im Merge-Labor: `scripts/webgui_userflow.py --spawn` und `scripts/webgui_chaos_run.py --spawn --rounds 200 --seed 42`. macOS startet das installierte Chrome, die Linux-CI das gebündelte Chromium. `verify_gui_dachboden.py` startet dieselbe Art Sitzung (`tmp/satsage-gui-session.json`) gegen eine Kopie der Lab-Env, im Labor-Job nach dem Quellen-Inventar. Die Präsentations-GUI ist dafür nicht nötig.
- Umfangreiche Labor-Läufe: erst den Nutzer das Ziel prüfen lassen (Root-HART), dann nur auf Angebot starten.
